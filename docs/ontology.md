# Ontology

The graph stores operational structure and a current-state projection. It does not store the order journal or the telemetry series. Those rows stay in SQLite, or in PostgreSQL when that adapter is actually used.

## Node labels

Factory, ProductionLine, Machine, Supplier, Material, Warehouse, InventoryLot, Product, ProductionOrder, CustomerOrder, TransportRoute, MaintenanceEvent.

`graph/schema.cypher` creates a uniqueness constraint on `id` for each label. The in-memory graph raises `ValueError` if the same machine id is added twice.

## Relationships

| From | Type | To |
| --- | --- | --- |
| Factory | HAS_LINE | ProductionLine |
| ProductionLine | HAS_MACHINE | Machine |
| Machine | PRODUCES | Product |
| Product | REQUIRES | Material |
| Supplier | SUPPLIES | Material |
| Warehouse | STORES | InventoryLot |
| InventoryLot | OF_MATERIAL | Material |
| ProductionOrder | PRODUCES | Product |
| ProductionOrder | SCHEDULED_AT | Factory |
| CustomerOrder | REQUESTS | Product |
| TransportRoute | CONNECTS_TO | Warehouse |
| MaintenanceEvent | AFFECTS | Machine |

DESTINED_TO and USES are extra types used by the catalog. They are in the whitelist with the types above. A label or relationship that is not in `graph/ontology.py` is rejected before any Cypher string is built. Identifiers and properties are query parameters.

Edge properties used on the hand scenario include `quantity_per_unit` on REQUIRES, `capacity_per_shift` on PRODUCES, `lead_time`, `capacity`, and `cost` on the route, and `valid_from`, `valid_to`, and `source_system` on catalog edges.

## Catalog size

`catalog.py` builds the seed with `random.Random(7)`. The measured counts are 190 entities and 1,027 relationships. After the failure event the graph also contains FAIL-001, so a live failure flow has 191 entities and 1,028 relationships. The benchmark file records the seeded catalog, before that maintenance node.

Products other than PRODUCT-A can REQUIRE SEAL-KIT-220. A material-shortage query can therefore return extra product rows. The PRESS-220 order query must return CO-2001 and must not return CO-2002.

## Entity resolution

`bind_alias` maps `(source_system, source_id)` to a canonical id and appends that pair to `source_identifiers` on the node. Resolving `synthetic-iot` / `SYN-SENSOR-220` returns PRESS-220. Resolving `synthetic-mes` / `PRESS-220` returns the same node. The original ids are not discarded.

## Two production-dependency shapes

`graph/queries/production_dependencies.cypher` is parameterized:

```
MATCH (po:ProductionOrder)-[:PRODUCES]->(p:Product {id: $product_id})
```

The in-memory `production_dependencies` helper returns every production-order row. Callers that need one product filter the list. The Cypher file does not.

## Seed file

`graph/seed.cypher` is generated by `scripts/generate_data.py` and `scripts/seed_graph.py`. It is a MERGE script for a server. The Python driver path uses parameters instead of interpolating property values. Do not hand-edit the generated file. Regenerate it.
